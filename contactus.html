Why Games, and Why AI?

Games are the most honest test of software I know. A game has to run smoothly sixty times a second, respond the instant you press a key, look good, sound right and still be fun. Nobody needs a manual to tell whether a racing game works: you just drive it.

That makes games a great way to find out what an AI coding agent can really build, and to show it to people who don't write code. My rule for this portal is simple: favourite game ideas, built with AI, using nothing but one HTML file and plain JavaScript. No game engine, no frameworks, no image files, no sound files and no server. Open the page and play, on a laptop or a phone.

Built Entirely with Claude Code

Every line of these games was written by Claude Code, Anthropic's AI coding agent, working in my own folder on my own laptop. I did not hand-write the code. I described what I wanted in plain words (often with a screenshot from my phone), played the result, and said what to change. Claude Code planned, wrote, ran and tested everything else, and published it to GitHub when I asked.

🧑 What I did

  • Picked the game and the open-source example to start from
  • Agreed the plan: art style, music, what version 1 should include
  • Asked for the fun extras: a driver who teaches, video recording, 3-minute races
  • Played every phase on my laptop and phone, and reported what felt wrong
  • Decided when it was ready to publish

🤖 What Claude Code did

  • Read the original 350-line demo, listed its bugs and gaps, and wrote the build plan
  • Rebuilt the road engine and drew every car, tree, sign and skyline in code
  • Generated all the sound live in the browser: engine, tyres, crashes, voice and music
  • Wrote the rival drivers, the coaching driver, the phone controls and the video recorder
  • Tested each phase in a headless browser, by clicking, steering and racing, before handing it over

Some examples of feedback turning into fixes:

"After the race was over it still kept making the car noise."The race now freezes on the results screen, a voice says "Game over", and music plays.
"The menu looks half cut on my phone."On phones the menus now scroll with the page instead of being squeezed into the game picture.
"There is no way to stop it."A ⏹ Stop button now shows on touch screens throughout a race and takes you straight back to the normal browser.
"My hired driver crashed 22 times in the rain."The driver now works out a safe speed for every bend ahead, allowing for wet grip: 0 crashes in the same test.

How You Can Play It, and Build on It

  1. Play it. Open the portal in any browser, on a laptop or phone. No sign-up, nothing to install. Start with Car Race, tick Hire a driver once to learn the track, then race on your own.
  2. Read how it was made. The Car Race build plan shows every phase, decision and test.
  3. Take the code. Everything is plain files in a public repository, github.com/RAGchamp/GAMES. Each game is a single HTML file you can open, read and change. Adding a new game to the portal is one line in a small list at the bottom of index.html.
  4. Build your own with Claude Code. You don't need to be a programmer to start. What worked for me:
    • Start from something small that already works (an open-source example) and ask for a written plan in phases before any code.
    • Describe what you want in plain words; paste a screenshot when it is easier to show than to tell.
    • Ask it to play its own game in a browser and check for errors, and to tell you honestly what it could not test (like a real phone or a real gamepad).
    • Test it yourself, especially on a phone, and say exactly what feels wrong. "No way to stop it" is perfect feedback.
    • Ask it to check that any music or pictures you want to reuse are allowed, before they go in.
A note on this project: these are personal learning projects, made for fun. Your scores, best laps and settings are saved only in your own browser, and nothing about you is sent anywhere. Car Race's road engine is based on the open-source "Javascript Racer" by Jake Gordon; everything else was drawn, composed and coded with AI.
