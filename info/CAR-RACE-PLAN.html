AI Games Portal

What is this plan and how does AI play a part?

This page is the build plan for Game 1: Car Race, the first game in the RAG Champ Games portal. The portal shows how an AI coding agent (Claude Code) can take a small open-source HTML/JavaScript example, read and understand it, fix its bugs and turn it into a richer game, using nothing but one HTML file and plain JavaScript. No frameworks, no build step, no server. PLEASE NOTE: players don't need any AI to play the games. The AI is used only to write the code.

2Starting point: what the original example does

Source: 234-car-race.html (source). It is "Javascript Racer v4 (final)", an open-source pseudo-3D racer in the style of classic arcade road games. It is a driving demo, not yet a game.

Rendering
Canvas 2D, pseudo-3D
Road segments projected as trapezoids, with rumble strips, lane lines, fog and 3 parallax layers (sky, hills, trees). Draws 300 segments ahead.
Game loop
Fixed 1/60 s step
An accumulator runs update(step), then render() once per animation frame. This is solid and worth keeping.
Traffic
200 cars, simple AI
Each car has a constant speed (3,000 to 9,000) and steers around slower cars and the player 20 segments ahead.
Goal / scoring
Lap times only
No score, no opponents to beat, no game over, no restart. The fastest lap is saved in localStorage.
Key tuning values (kept as defaults) roadWidth 2000segmentLength 200lanes 3FOV 100cameraHeight 1000drawDistance 300centrifugal 0.3maxSpeed 12000accel = max/5off-road limit = max/4

Road builder helpers we will reuse: addRoad, addStraight, addHill, addCurve, addSCurves, addBumps, addLowRollingHills, addDownhillToEnd. Helpers: Util.project, Util.overlap, easeIn/Out, exponentialFog.

3Problems in the original we will fix
#ProblemFix
1Needs 2 PNG sprite sheets; if one fails to load the game stays on "Loading…" foreverDraw everything procedurally on canvas. No assets to load.
2Keys use deprecated keyCode; a missed key-up (e.g. tab switch) leaves the car steeringUse event.code, clear all keys on window blur, auto-pause when the tab is hidden.
3Undeclared index variable in updateCars (accidental global)Declare locally; run the whole script in 'use strict'.
4offRoadDecel declared twice; dead code; duplicate id="fps"Remove dead code and the Stats FPS widget (optional debug toggle instead).
5Music autoplays without a user gesture (blocked by browsers, unhandled promise)Start all audio from the "Start race" click using the Web Audio API.
6Traffic ignores lanes; the lanes setting only changes the painted linesRivals and traffic pick lanes and change lanes on purpose.
7Speed shown as 5 × round(speed/500), not a real unitShow a scaled km/h value (0 to 300) on an arc speedometer.
8First lap is not recorded; lap time stored as a stringStart the clock at "GO!", store numbers, show lap splits.
9Old Google Analytics snippet and developer tuning panelRemove analytics. Hide the tuning sliders behind a "Settings" drawer.
10Fixed 640×480 canvas, no phone supportResponsive canvas (keeps 4:3 or 16:9), on-screen touch pedals and tilt steering.

5Code structure inside car-race.html

One file, organised into clearly commented sections so readers can follow how the AI built it:

  1. CONFIG: all tuning constants in one object.
  2. UTIL: maths, easing, projection, overlap (from the original).
  3. INPUT: keyboard, touch, gamepad → one controls object.
  4. AUDIO: Web Audio context, engine oscillator, synthesised effects.
  5. TRACKS: road builder plus 3 track recipes and themes (colours, scenery list).
  6. SPRITES: procedural drawing functions (car, truck, palm, cactus, rock, lamp, sign, coin), cached to off-screen canvases once at start.
  1. ENTITIES: player, rivals, traffic, pickups.
  2. PHYSICS: speed, steering, centrifugal force, off-road, collisions, nitro, damage.
  3. RACE: laps, checkpoints, positions, timers and the mode rules.
  4. RENDER: background, road, sprites back-to-front, effects (shake, speed lines, rain).
  5. HUD and SCREENS: canvas HUD; HTML overlays for title, pause and results.
  6. STATE MACHINE: title → countdown → racing ⇄ paused → results.

Performance target: steady 60 fps on a mid-range laptop and phone. Sprites are drawn once to off-screen canvases and then blitted. The canvas renders at device pixel ratio, capped at 2.

  • HUD: speedometer, position, laps, lap times, nitro, mini-map.
Done when: a 3-lap Grand Prix can be won or lost, the position updates correctly when overtaking, and results show the right order.

  • Coins, nitro cans and repairs; score.

Phase 4: More content and devices ✅ Done 20 Nov 2026 Play it →

  • Desert Canyon and Neon City tracks; optional rain.
  • Time Attack and Endless Traffic modes; difficulty levels.
  • Touch pedals, optional tilt and gamepad; local leaderboard. (Also: night headlights, tail-light and street-lamp glows on Neon City; tapping Start goes full screen on phones where the browser allows it.)

Extras (requested after Phase 4) ✅ Done 20 Nov 2026

  • 🧑‍✈️ Hire a driver: a computer driver races your car while a coaching box at the top shows which controls it is pressing, what it is doing and why, plus a driving tip. Press H to take over or hand back. Driver-assisted races are not added to the top 5.
  • 🎥 Record video: records the game picture and sound with the browser's MediaRecorder and offers a Download video button (.webm in Chrome, Edge and Firefox). Tick it on the title screen to film each race automatically, or use the toolbar button at any time. The HUD is drawn into the video.
  • Race length: Short stops exactly 3 minutes after GO (in the Grand Prix the order at that moment is the result); Long is the full 3 laps (no limit in Time Attack and Endless). Short and Long keep separate top-5 lists.

9Test checklist
  • Opens from file:/// in Chrome, Edge and Firefox; no console errors.
  • 60 fps on a laptop; playable (30+ fps) on a phone.
  • Switching tabs pauses the game; no stuck keys afterwards.
  • Lap counting is right on every lap, including the first.
  • Positions are correct when lapping or being lapped.
  • Game still works in a private window (localStorage blocked).
  • Resizing or rotating the phone keeps the canvas sharp and centred.
  • Mute works and is remembered; no sound before the first click.
10Decisions (agreed 20 Nov 2026) and credits
  • Art style: drawn in code. Cars, scenery and sky are procedural canvas drawings, with no image files.
  • Version 1 scope: up to Phase 3. A Grand Prix on one track with nitro, crashes, pickups and sound. Phases 4 and 5 follow.
  • Music: sound effects only. Engine, screech, crash, coin and nitro sounds are synthesised with Web Audio. No background music.
  • Portal links: none for now. The Games portal stays standalone and is not linked from the Music site or Site Map until it is ready.
  • Credits: the road engine is based on the open-source "Javascript Racer" by Jake Gordon (MIT licence), as republished in the flathtml 800 Examples collection. The game file and the info page will keep that credit and licence notice.
