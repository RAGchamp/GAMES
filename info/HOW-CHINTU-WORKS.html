What is this page and how does AI play a part?

This page explains how Game 2: Chintu works inside: how the levels are written, how jumping feels right, how the game knows when red light can see an invisible boy, and what Claude Code (an AI coding agent) built, phase by phase. The whole game was written by Claude Code from a short story idea and two character pictures, and tested on a computer and on a phone by a person. Players don't need any AI to play. The small demos on this page use the same rules and numbers as the game, so you can try them yourself.

1One file and the game loop

Chintu is a single web page. There is no game engine, no framework and no server: it opens with a double-click. The picture is drawn on a canvas, a rectangle the code can paint on. 60 times a second the game moves everything a tiny step and then paints a new picture.

1 · Read the controlsKeyboard, touch buttons or a gamepad: RUN, BACK, JUMP.
→
2 · Update (1/60 s steps)Move Chintu, goons, coconuts, carpets, barrels; check hits, lights and pickups.
→
3 · DrawSky, parallax town, tiles, characters, light beams, then the HUD on top.
→
4 · MusicPlan the next notes of the music loop, a fraction of a second ahead.

The update always moves time forward in exact steps of 1/60 of a second, even if the screen is slower or faster. That way a jump is the same height on a fast computer and on a slow phone. If a frame takes longer, the game simply does two or three steps before drawing.

The game is drawn 270 "game pixels" tall (and 480 wide on a 16:9 screen), then scaled up to fit the screen. Phones get at most 3 screen pixels per game pixel, and if a device runs slower than 45 frames a second the game first switches off glow effects, then draws with fewer pixels.

The heart of the main loop (from chintu.html) 
// time since the last frame, never more than 0.25 s
acc += dt;
while (acc >= STEP) {     // STEP = 1/60 s
  update(STEP);            // move everything one step
  acc -= STEP;
}
render();                  // draw the new picture
snd.music(wantedMusic());  // keep the music going
2Levels are written as text

Every stage is made of small pieces, and every piece is 11 rows of text characters. Each character is one tile, 30 game pixels square: = is ground, ? is a block to bump, g is a goon, and so on. A stage is just a list of piece names joined end to end, so a new stage needs no new code.

A stage (from chintu.html) 
{ id: '1-1', world: 1, name: 'Village Lanes', par: 75, worry: [0, 8],
  pieces: ['start1', 'coins', 'blocks', 'goonHint', 'pothole',
           'cow', 'gapHint', 'stepsPage', 'checkpoint', ...] }

par is the target time in seconds (the third star) and worry says how worried Dr. Andhera gets from the start to the end of the stage.

A piece (rows not given are sky, rows 9 and 10 are ground) 
goons2: C(24, {
  5: '.........oo.............',   // two laddoos
  6: '........####............',   // a brick ledge
  8: '.......g.......g........',   // two goons
})

When a stage loads, the game reads the text row by row: tiles such as ground and blocks stay in the map, and characters such as goons, laddoos and lights are taken out and turned into moving objects.

3Running and jumping (the physics)

Chintu has a speed across (vx) and a speed up and down (vy). Every step, gravity adds to vy, which pulls him down faster and faster, and both speeds move him a little. A jump simply sets vy to a big upward number.

SettingValueWhat it does
gravity1800Pulls down, in game pixels per second, per second
jump speed620Upward speed at the start of a jump
double jump560A second, smaller jump in the air (World 2 onwards)
let go early× 0.45Releasing JUMP while rising cuts the speed: a short hop
run speed185Top speed while RUN is held
coyote time0.1 sYou can still jump just after running off an edge
jump buffer0.12 sA press just before landing still counts

The highest jump is about speed² ÷ (2 × gravity) = 620² ÷ 3600 ≈ 107 game pixels. Because the game moves in 1/60-second steps it comes out a little lower, about 102 game pixels (3.4 tiles), so a wall 3 tiles high needs a held jump. Coyote time and the jump buffer are small kindnesses that make the controls feel fair: without them, presses that are a few hundredths of a second early or late would be lost.

Jumping (from chintu.html) 
// pressed recently, and on the ground (or just off an edge)?
if (p.jumpBuf > 0 && p.coyoteT > 0) p.vy = -PHYS.jumpV;
// let go while still rising: a shorter jump
if (p.jumping && !input.jump && p.vy < 0) p.vy *= PHYS.jumpCut;
// gravity, with a top falling speed
p.vy = Math.min(PHYS.maxFall, p.vy + PHYS.gravity * dt);

Bumping into things: the game moves Chintu across first and pushes him out of any solid tile he entered, then moves him up or down and does the same. Planks and awnings only hold him if his feet were above them a moment ago, so he can jump up through them. Stomping counts when he is falling and his feet were above the goon's head a moment ago; touching a goon any other way costs a heart.

4The red-light check

The heart of the story: the formula makes Chintu invisible, but red light still shows him. Every searchlight, drone lamp, sentry torch and alarm lamp is a beam: a cone with a starting point, a direction, a width and a length. Every step the game asks one question for three points on Chintu (his head, his middle and his feet): is this point inside a beam?

Is a point inside a cone? (from chintu.html) 
function inBeam(b, px, py) {
  const dx = px - b.x, dy = py - b.y;
  const d = Math.hypot(dx, dy);       // how far from the lamp
  if (d > b.len || d < 2) return false;
  const a = Math.atan2(dy, dx);       // which direction
  // is that direction within half the cone's width of the beam's direction?
  return Math.abs(Math.atan2(Math.sin(a - b.ang),
                             Math.cos(a - b.ang))) < b.half;
}
The rule 
seen = inRed || (inWhite && !invisible);
revealed = invisible && inRed;   // draw the red glow
  • White light sees a normal Chintu, but not an invisible one.
  • Red light sees him either way, and draws him as a glowing red outline.
  • Being seen sets off an alarm, and a cage drops where he stands (at most once every 3 seconds).
  • The atan2(sin, cos) trick turns any angle difference into the range −180° to 180°, so a beam pointing right (0°) and a point just below it (−5° or 355°) are correctly 5° apart.

5Dr. Andhera's worry meter and the boss

The worry meter in the HUD is a number from 0 to 100. Each stage has a start and end value, and the meter moves between them as Chintu gets closer to the finish. Pages make Dr. Andhera more worried; hits and alarms calm him down a little:

worry = start + (end − start) × progress
        + pages × 2 − hits × 2 − alarms × 3

Below 25 he is 😏 calm, then 😠 annoyed, 😰 worried and, from 75, 😡 furious. His face in the HUD and in the control-room scenes is drawn with code in four moods, and a ship horn sounds when his mood goes up.

In the vault, the same light rule decides whether Dr. Andhera can see Chintu:

heSees = !lightsOut && (!invisible || inRedLamp);

When he can see Chintu he aims each barrel: he works out how long a barrel takes to fall to the floor (t = (−vy + √(vy² + 2·g·drop)) ÷ g) and throws it just fast enough sideways to land where Chintu is. When he can't, he throws blindly and less often. Each switch Chintu jumps on breaks one lamp; with fewer lamps the dark gaps grow, and in the 3 rounds the barrels get faster. With all 4 lamps broken, he can't see at all.

6Drawing and sound, all with code

Pictures. There are no image files. Chintu is a set of shapes: a head, a body and four limbs, each limb a thick line at an angle. Running is the legs' angles swinging with a sine wave; jumping, falling, sliding, getting hurt and the victory hop are different sets of angles. Goons, the sleeping cow, Dr. Andhera, the vault and every tile are drawn the same way.

Depth. The background is drawn in layers (sky, far town, near houses) that move slower than the ground as the camera follows Chintu. This is called parallax, and it makes a flat picture feel deep. Light beams are drawn with "lighter" blending, so overlapping beams glow brighter.

Sound. Every sound effect and every music loop is made while the game runs, with the browser's Web Audio: a wave of a chosen shape, a pitch that may slide, and a volume that fades. Nothing plays until the first tap or key press. The one recording is a ship horn that warns when danger is coming.

Each of the 31 sound effects and 6 music loops, with its code and a Play button, is on the 🔊 sound effects page, along with future sounds made from recordings for characters in later versions.

How it was checked
  • A computer player. The game has a built-in bot (open the game with ?demo) that runs, jumps gaps and goons, and waits for laser gates. After each change it played every stage in a test browser to prove each one can still be finished.
  • Automatic browser tests started stages, jumped on the boss switches, opened every menu, checked that no sound plays before the first tap, measured frames per second on a slowed-down phone screen, and looked for any error.
  • Screenshots of every new screen were checked by eye, which found things such as lamps hidden behind the score display.
  • People played it on a real phone, which found the things a computer can't feel: auto-run was hard to control, and the buttons were cut off when the phone was held sideways.
